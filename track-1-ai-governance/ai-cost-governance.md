# KP Vitals — AI Cost Governance

## Purpose

AI governance includes financial governance.

An agentic workflow may make multiple model calls, use external tools, retry failed steps, and escalate to human review. Therefore, the cost of an AI workflow should be governed at the workflow and outcome level rather than looking only at the price of an individual model call.

This artifact applies cost-governance and FinOps concepts to the KP Vitals portfolio use case.

## Cost Governance Questions

The governance team should understand:

- What does one successful workflow run cost?
- How many AI/model calls occur within one run?
- How frequently are retries occurring?
- Which steps require a more capable model?
- Which steps can use lower-cost deterministic automation or smaller models?
- What happens when a workflow exceeds its expected run budget?
- Is increased AI spending producing measurable operational value?

## Cost Measurement Levels

| Measure | Meaning | Governance Value |
|---|---|---|
| Cost per call | Cost of an individual model/API interaction | Useful for model-level monitoring |
| Cost per run | Total cost of completing one workflow execution | Shows workflow operating cost |
| Cost per successful outcome | Total AI/workflow cost divided by successful outcomes | Connects spending to actual value |
| Retry cost | Cost generated by repeated or failed attempts | Identifies inefficiency |
| Human-review cost | Cost/time associated with required human intervention | Helps evaluate total workflow economics |

## Per-Run Budget Governance

Each workflow should have an expected operating-cost range.

Controls may include:

- Maximum number of model calls per run
- Retry limits
- Token or usage thresholds
- Alerts when run cost exceeds defined limits
- Escalation when repeated failures increase cost
- Logging of model and tool usage
- Periodic review of cost-per-successful-outcome

A workflow should not be allowed to consume resources indefinitely because an AI step repeatedly fails or retries.

## Model Right-Sizing

The most capable model does not need to perform every workflow step.

Lower-cost models or deterministic automation may be appropriate for routine classification, formatting, routing, or validation.

More capable models should be reserved for tasks requiring greater reasoning or handling of complex uncertainty.

This supports both cost efficiency and appropriate governance.

## KP Vitals Example

A conceptual KP Vitals run might involve:

**Vitals received → validation → AI interpretation → risk classification → routing/escalation → human review where required → outcome logged**

Cost governance evaluates the entire run rather than treating the AI interpretation call as the total cost of the workflow.

If repeated retries, unnecessary model calls, or excessive human overrides occur, the cost per successful outcome may increase even when the individual AI call appears inexpensive.

## Cost Guardrails

Potential governance guardrails include:

- Per-run budget threshold
- Maximum retry count
- Maximum model-call count
- Model-routing policy
- Cost anomaly alerts
- Human approval for unusually expensive exception paths
- Monthly cost-versus-outcome review

## FinOps Principle

AI spending should be connected to accountability and measurable business value.

The objective is not simply to minimize AI cost.

The objective is to optimize:

**Cost + Reliability + Risk + Business/Clinical Value**

A more expensive workflow may be justified if it produces materially better outcomes, while a low-cost workflow that frequently fails or requires rework may represent poor value.

## Key Cost Indicators

Monitor:

- Cost per run
- Cost per successful outcome
- Model calls per run
- Retry rate
- Token/usage consumption
- Human intervention rate
- Cost variance from expected baseline
- Value generated relative to operating cost
